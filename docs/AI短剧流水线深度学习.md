## 一、通用 8 阶段主线（从 5 个高星项目收敛）

把 huobao-drama / Drama Skills / Toonflow / ViMax / Open-Micro-Drama 的流水线对齐，抽象出一条**通用主线**。任何短剧 skill 都能往这 8 个槽位里填：

| 阶段 | 名称 | 输入 → 输出 | 关键动作 |
|---|---|---|---|
| 1 | **输入与剧本理解** | 原著/idea/脚本 → 结构化剧情单元 | 事件图谱、章节索引、节奏提取 |
| 2 | **剧本结构化** | 剧情 → 故事引擎/分集地图/分场剧本 | 因果节拍、可拍剧本、导演阐述 |
| 3 | **资产决策与一致性锁** | 剧本 → 人物/场景/道具 + 造型锁 | 四实体拆分、参考图锚定、连续性锁短语 |
| 4 | **分镜设计** | 分场 → 镜头表（景别/运镜/音效/时长） | Coverage Audition、冻结关键帧 |
| 5 | **提示词工程** | 分镜 → 图片提示词 + 视频提示词 | 锚点技术、起止状态、跨镜时间线 |
| 6 | **视觉生成** | 提示词 → 参考图→首帧(I2I)→视频(I2V) | 并行生成、VLM 选最佳首帧 |
| 7 | **配音与合成** | 视频+台词 → 配音/数字人/成片 | TTS+声音克隆、口型驱动、moviepy/ffmpeg 拼接 |
| 8 | **质检与人工审核闸** | 成片 → 通过/返工 | VLM QC、核对脚本、自动重生成 |

> **一句话**：1-2 是"想清楚拍什么"，3-5 是"锁死长什么样"，6-7 是"生产素材"，8 是"把关"。

## 二、逐项目拆解：它们各自怎么排这条线

### 2.1 Drama Skills（zenstory-ai · MIT · 11 skills）— 最该抄的"产线规范"范本
- **定位**：唯一开源 + 全流程 + Agent Skills 标准的 AI 短剧产线；来自真实漫剧工作室（跑过上千项目）。
- **11 个技能**：`short-drama`(总路由/看板) → `novel-analyze`(原著分析) → `develop`(故事开发/分集地图) → `write`(单集可拍剧本) → `assets`(人物/场景/道具+声音方向) → `image-prompts`(参考板提示词) → `storyboard`(分镜/冻结关键帧) → `video-prompts`(逐镜视频提示词) → `produce`(预览确认后执行) → `edit`(剪辑单) → `review`(审查)。
- **5 份 Markdown = 创作事实**（没有数据库，改文件即改决定）：
  1. `剧本.md`（故事发生什么）
  2. `视觉设定.md`（跨镜造型锁）
  3. `分镜.md`（每镜起止 + 冻结关键帧）
  4. `图片提示词.md`（直接喂图模型）
  5. `视频提示词.md`（直接喂视频模型）+ 剪辑时多一份 `剪辑单.md`
- **连续性锁**：跨镜要保持的造型写成"能原样贴进提示词的短语"，例如 `LOCK-JIANGCHEN-DRESS《江晨橄榄绿立领常服》` → 锁面 `olive-green stand-collar service dress`。每镜写完关键帧要说明依据了哪些条目，**核对脚本会揪出漏掉的**。
- **预览确认闸门**：任何图片/视频/TTS/音乐任务，**先在文件里看到准确内容和参数，明确确认后才调用外部接口花钱**。视频任务提交即计费，断了不重投，用 `collect --job-id` 取回。
- **自带核对脚本**：`creator_markdown_check.py` 核对 5 份文档引用关系；`edit_tool.py check` 核对剪辑单（报的是**原因**不是"校验失败"）。
- **适配模型**：Seedance / GPT Image 2 / MiniMax H3 / MiniMax Music；写作用 Claude/Codex 自带模型。
- **可抄点**：① 文件即事实的"创作事实"范式 ② 连续性锁短语 ③ 预览确认闸 ④ 核对脚本（把一致性规则机器化）。
- **坑**：强制逐步确认比"一键生视频"慢（设计如此）；依赖 Agent 订阅。

### 2.2 Open-AI-Micro-Drama-Generator（Anil-matcha）— 最清晰的 8 阶段**代码实现**
- **定位**：把"想法→成片"落成显式 8 阶段 + 单 API Key（MuAPI）跑通全流程，最适合照抄工程结构。
- **8 阶段（每阶段标注 Agent/Tool/Output）**：
  1. 故事开发 — Screenwriter(LLM) → 散文大纲
  2. 角色提取 — CharacterExtractor(LLM) → 角色静态+动态视觉特征
  3. 场景脚本 — Screenwriter(LLM) → 2–4 个场景脚本
  4. 角色肖像 — `flux-dev-image`(T2I) → 每角色参考肖像 **（并行）**
  5. 分镜设计 — StoryboardArtist(LLM) → 每场景 3–5 镜（视觉+动作+音频描述）
  6. 帧生成 — `flux-kontext-dev-i2i`(I2I) → 用角色参考图生成每镜首帧
  7. 视频生成 — `kling-v2.1-standard-i2v`(I2V) → 每镜 5 秒 **（并行）**
  8. 拼接 — `moviepy` → `final_video.mp4`
- **短流水线**：跳过 1–3，直接从你提供的脚本开始（5 阶段）。
- **结构**：`server/`(FastAPI + SSE 任务流) / `agents/`(screenwriter, character_extractor, storyboard_artist) / `interfaces/`(Pydantic 数据模型) / `tools/`(MuAPI 集成层)。**数据模型先定义**（`CharacterInScene`、`ShotBriefDescription`）是它能稳定串联的关键。
- **可抄点**：① 阶段-工具-输出的显式映射表 ② 肖像并行 + 视频并行 ③ 先定义数据模型再写流程 ④ 单 Key 降门槛。

### 2.3 Toonflow（HBAI-Ltd · Apache-2.0）— 三层 Agent + 工业化的"超导体"工作流
- **定位**：小说/剧本 → 动画短剧的一站式工作台；重构了创作流水线让各环节**并行**。
- **三层 Agent 架构**：
  - 决策层 `ScriptAgent`：用**蒙特卡洛树搜索(MCTS)**评估剧本分支，关键情节用户留存率 +42%；自动规避高流失桥段。
  - 执行层 `ProductionAgent`：**17 个专用子模块**（镜头计算器按情感值匹配景别、运镜规划器、灯光配置器…），用 **DAG 有向无环图调度**，视频时长误差 ±5%。
  - 监督层：对比百万级优质视频训练的判别模型，检测构图/节奏/穿帮，**自动触发重生成**形成负反馈。
- **事件图谱引擎**：把原著按章节事件结构化存储，剧本改编精准调用上下文，减少长文本信息丢失。
- **持久化 Agent 记忆**：本地 ONNX 向量检索（all-MiniLM-L6-v2），跨会话短期消息/长期摘要/语义召回——AI 记住你改了什么。
- **可编程供应商系统**：设置中心直接写 TypeScript 逻辑即时生效，不被单一模型锁死。
- **无限画布**：节点化组织分镜/素材/视频，自由编排、回溯、并行生产。
- **成本数据**：官方 Demo ≈2 小时完成、成片 2 分钟，总成本 ≈¥130（LLM ¥10 + 视频 ¥120 + 图片 <¥1）。
- **可抄点**：① 三层 Agent（生成+质检+返工闭环）② MCTS 剧本分支评估 ③ DAG 调度 ④ 向量记忆跨会话 ⑤ 供应商可插拔。
- **坑**：重构后运行环境/许可证有变化，装旧版要先选定版本。

### 2.4 ViMax（HKUDS · MIT · ~1.4k⭐ · 有 arXiv 2606.07649）— 8 层 + 学术背书的框架
- **定位**：端到端多智能体视频生成，把影视制作每环节搬进 AI；**有论文**支撑其一致性/叙事机制。
- **8 层多智能体流水线**：输入层 → 中央编排(调度/阶段过渡/重试降级) → 剧本理解(角色环境提取/场景边界/风格意图) → 场景与镜头规划(分镜/镜头列表/关键帧节奏) → 视觉资产管理(参考图选择/风格引导/Prompt 条件) → 资产索引(帧/参考图分类+嵌入+复用检索) → 一致性保障(角色环境追踪/参考图匹配/时序连贯) → 视觉合成与组装(图像生成/最佳首帧选择/首尾帧→视频/剪辑时间线)。
- **4 大模式**：Idea2Video / Novel2Video(叙事压缩+剧集拆分) / Script2Video / AutoCameo(上传照片客串)。
- **三大技术支柱**：
  - **层级叙事引擎 + RAG**：全局故事连贯，解决长视频"灾难性语义遗忘"。
  - **依赖感知视觉一致性机制**：跨时序边界追踪角色/环境状态（对象级一致性）。
  - **VLM 引导 QC**：并行生成多图，用多模态模型选最佳首帧，模仿人类创作者。
- **聪明细节**：智能参考图选择会纳入"前序时间线的分镜"保证长视频多角色准确；多相机拍摄模拟保持同场景角色定位/背景一致；同一相机顺序镜头**并行生成**。
- **模型配置示例**：chat=gemini-2.5-flash-lite，image=nanobanana，video=veo，全部走 OpenRouter 一个 Key。
- **可抄点**：① 8 层抽象（尤其"资产索引/一致性保障"独立成层）② RAG 叙事 ③ VLM 选帧 ④ 重试/降级容错。

### 2.5 FilmAgent（HITsz-TMG）& 深圳工厂（MIT 报道）— 两端参考
- **FilmAgent**：多智能体在**虚拟 3D 空间**(Unity) 自动化拍短片；导演/编剧/演员/摄影师互提意见；Critique-Correct-Verify + Debate-Judge 协作；ChatTTS 配音。强在情节连贯，**但需要预搭 3D 场景**。
- **深圳工厂 / Dragon Heir（MIT 2026-03）**：自定义 LLM 在 **5 万成功剧本**上微调，强制 **60 字/集 + 每集结尾悬念**；TTS 每集批量生成 6 个角色声线；ControlNet 扩散模型微调 2D 国漫；Python 规则引擎按音频强度剪辑。**单集成本 ≈$0.12，每周 800 集/产线**。
  - **启示**：数据质量 > 模型花哨；"句子级结构—留存"对应关系是它的真壁垒。

## 三、流水线最难的三件事 + 各项目解法

| 难题 | 解法（来自高星项目） |
|---|---|
| **① 跨镜一致性**（同一人换镜头变脸） | 参考图(最强) + 首帧锚定(杠杆最高) + 提示词锚点(补细节) + 造型锁短语(Drama Skills) + VLM QC(ViMax/Toonflow) |
| **② 长文本/长视频叙事连贯** | 事件图谱(Toonflow) / 层级叙事引擎+RAG(ViMax) / 5 万剧本微调强制结构(深圳工厂) |
| **③ 成本与速度** | 并行生成(肖像/视频并行, Open-Micro-Drama+ViMax) / 预览确认闸(Drama Skills, 避免乱花钱) / 单 Key 降门槛 / 分层渲染(背景+角色分开) |

## 四、一致性技术深挖：Lock-Then-Animate 四机制（流水线命脉）

业界 2026 共识：**先用图像模型锁定身份，再让视频模型碰它**（图像模型在"身份"上远强于视频模型）。四机制要**同时全开**：

1. **参考图像（最强）**：喂 2–6 张角色照，IP-Adapter/DreamBooth 脉络；现代多参考模型（Nano Banana 2 / Seedream / FLUX.2）可同时接受多张。
2. **起始帧锚定（杠杆最高单个技巧）**：角色图即视频第一帧，模型不必重新想象这张脸。
3. **模型内置主体特征（片内追踪）**：Kling 3.0 在片段内持续追踪身份，减片内漂移，但解决不了跨场景。
4. **提示词锚点（最弱但值得）**：一段逐字不变的角色描述粘贴进每条 prompt（名字/数字年龄/镜头可能漏的细节）。

**最小角色设定表（5 张）**：正面 / 四分之三左 / 四分之三右 / 侧面 / 微笑特写。更多需求扩到 10–15 张（多 outfit/多表情）。换装不换脸用 **Flux Kontext 区域编辑**（只改你 mask 的区域）。下游每个新镜头都是"多参考生成"，不是"重新文生图赌博"。

> 实测（PixMind 30 镜头）：双锚（参考图+文字身份模块）稳定 24/30；只用文字锁 9/30 → **约 2.7 倍提升**。

## 五、多 Agent 编排模式对比（选型参考）

| 模式 | 代表 | 适合 | 复杂度 |
|---|---|---|---|
| **顺序流水线**（阶段-工具映射） | Open-Micro-Drama | 想最快跑通、结构清晰 | ★★ |
| **总路由 + 专用 skill**（文件即事实） | Drama Skills | 要创作控制权、可审计 | ★★★ |
| **三层 Agent + DAG**（生成+质检+返工） | Toonflow | 工业化、自动化闭环 | ★★★★ |
| **8 层 + 中央编排**（RAG+VLM QC） | ViMax | 长视频、学术级一致 | ★★★★ |
| **虚拟 3D 角色协作** | FilmAgent | 强叙事、愿搭 3D 场景 | ★★★★★ |

**选型建议**：个人/小团队起步用"顺序流水线 + Drama Skills 的文件即事实 + 确认闸"最稳；想上量再叠 Toonflow 式三层 Agent 与 VLM QC。

## 六、给我们自己的短剧 Skill 的流水线升级方案

基于 Drama Skills 的范式，把我们仓库 `ai-short-drama-skill/SKILL.md` 升级为**生产级**，建议改造点：

1. **引入"创作事实"5 文件**：`剧本.md / 视觉设定.md / 分镜.md / 图片提示词.md / 视频提示词.md`，替代单文件脑内记忆。
2. **加连续性锁短语**：角色造型写成可贴提示词的锁面（如 `LOCK-<角色>-<部件>《中文名》` → 英文锁面）。
3. **加预览确认闸**：所有收费生成前先输出"参数预览块"，明确确认才调外部接口。
4. **加核对脚本思想**：在 SKILL 里写"分镜来源必须引视觉设定条目，否则报错"的硬规则。
5. **拆成 11 个路由 skill**（对齐 Drama Skills）或至少保留 `short-drama` 总路由 + 分阶段子流程。
6. **锚点技术写进 video-prompts 阶段**：参考图 + 首帧 + 提示词锚点三件套。
